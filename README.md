# Код без ошибок

Неофициальный сайт для подготовки к экзамену по курсу «Алгебраическая теория кодирования» (АТК): теория с нуля, разобранные примеры, задачи с подсказками, подготовка к устному экзамену, словарь и тренажёры.

Сайт статический: только HTML, CSS и JavaScript. Сервер, база данных, регистрация и ключи API не нужны, поэтому его можно бесплатно разместить на GitHub Pages. Все ссылки относительные, так что сайт работает и в корне домена, и по адресу вида `https://<пользователь>.github.io/<репозиторий>/`.

## Как посмотреть сайт у себя на компьютере

Самый простой способ — открыть файл `index.html` двойным щелчком. Работает всё: меню, поиск, формулы, тренажёры, прогресс.

Чтобы проверить «как на сервере», запустите в папке проекта:

```bash
python3 -m http.server 8000
```

и откройте `http://localhost:8000`. Остановить сервер — `Ctrl+C`.

## Публикация на GitHub Pages

### Первый раз

1. На [github.com](https://github.com) нажмите **New repository**, придумайте имя (например, `atk-exam-prep`) и выберите **Public**: бесплатный GitHub Pages работает с публичными репозиториями.
2. Загрузите файлы проекта в ветку `main` (команды ниже, в разделе «Ветки»).
3. В репозитории откройте **Settings → Pages**. В блоке **Build and deployment** выберите **Source: GitHub Actions**.
4. Откройте вкладку **Actions**: там запустится «Проверка и публикация сайта». Если он не запустился сам, выберите его слева и нажмите **Run workflow**.
5. Через 1–2 минуты сайт появится по адресу `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`. Ссылка будет показана в **Settings → Pages** и в результате запуска на вкладке **Actions**.

Workflow (`.github/workflows/pages.yml`) при каждом push:
- в любую из веток `unstable` и `main` проверяет, что сайт собран и в нём нет битых ссылок и якорей;
- из ветки `main` дополнительно публикует сайт. Служебные файлы (`dev/`, `.github/`, `README.md`) на сайт не попадают.

Если проверка не прошла, на вкладке **Actions** будет красный крестик, а в журнале — строки «ОШИБКА: …». Сайт при этом не обновится, и останется прежняя рабочая версия.

### Запасной вариант без Actions

В **Settings → Pages** можно выбрать **Source: Deploy from a branch**, ветку **`main`** и папку **`/ (root)`**. Сайт будет работать так же, только без автоматической проверки, а служебные файлы тоже окажутся в открытом доступе (ничего секретного в них нет). Файл `.nojekyll` нужен именно для этого варианта, не удаляйте его.

## Ветки: `unstable` и `main`

- `unstable` — для новых модулей и проверки обновлений.
- `main` — готовая версия, она и публикуется.

```bash
git checkout unstable
# распакуйте новый архив поверх файлов проекта
git add -A
git commit -m "Модуль 2: линейная алгебра"
git push            # GitHub проверит сборку, результат — на вкладке Actions

# проверили локально и в Actions — переносим в main
git checkout main
git merge unstable
git push            # GitHub проверит и опубликует сайт
```

`git add -A` учитывает и удалённые файлы. Если при распаковке поверх какой-то файл из старой версии остался, а в новой его нет, он перечислен в описании обновления — удалите его (`git rm путь/к/файлу`).

## Что сайт запоминает

Всё хранится в `localStorage` браузера на этом устройстве под ключом `atk-kbo:progress` и никуда не отправляется:

- статус каждого модуля: предстоит, изучается или пройдено;
- прочитанные блоки теории и решённые задачи;
- заметки к задачам (поле «Заметки»);
- выбранные ответы в тестах, последний и лучший результат;
- отрепетированные вопросы устного экзамена;
- место, где вы остановились (кнопка «Продолжить» на главной);
- выбранную тему: светлая (по умолчанию) или тёмная, ключ `atk-kbo:theme`. Настройка темы в браузере или системе не учитывается.

На другое устройство данные сами не переносятся. Для переноса на странице «План» есть кнопки «Сохранить прогресс в файл» и «Загрузить из файла». Там же можно стереть прогресс: подтверждение появляется прямо на странице.

Если браузер запрещает хранить данные (например, в приватном режиме), сайт покажет предупреждение и будет хранить прогресс только до закрытия вкладки.

## Для того, кто обновляет сайт

Нужен только Python 3.8+ без дополнительных библиотек.

```bash
python3 dev/build.py                 # собрать и проверить
python3 dev/build.py --check         # только проверить (так делает GitHub Actions)
python3 dev/build.py dist            # собрать папку _site с публикуемыми файлами
python3 dev/build.py new-module m02 "Линейная алгебра над конечным полем"
```

**Общие части страниц.** `<head>`, шапка и подвал вставляются сборкой между метками `<!-- @head -->…<!-- /@head -->`, `<!-- @header -->…<!-- /@header -->`, `<!-- @footer -->…<!-- /@footer -->`. Заголовок и описание страницы берутся из атрибутов `data-title` и `data-desc` тега `<body>`, активный пункт меню — из `data-page`, дополнительные скрипты — из `data-scripts`. KaTeX подключается сам, если на странице есть формулы `\( … \)` или `\[ … \]`.

**Новый модуль:**
1. `python3 dev/build.py new-module m02 "Название"` создаст четыре страницы из `dev/templates/`.
2. Заполните их. Идентификаторы прогресса: задачи — `data-task="m02-t1"`, блоки теории — `data-block="m02-b1"`, тест — `<form class="quiz" id="quiz-m02">`, заметки к задачам — `data-note` с тем же значением, что у задачи.
3. В `dev/modules.json` поставьте модулю `"ready": true` и обновите `questionCoverage`: `"ready"` — вопрос разобран полностью, `"partial"` — частично. Пометки у вопросов на странице устного экзамена сборка расставит сама.
4. Поднимите `version` и `updated` в `dev/modules.json`, добавьте строку в «Что нового» на главной и в историю версий ниже.
5. Запустите `python3 dev/build.py`. Сборка проверит ссылки, якоря, повторяющиеся `id`, идентификаторы прогресса и встроенные стили.

**Идентификаторы прогресса не переименовывайте.** По ним хранится прогресс у всех, кто уже пользуется сайтом. Задачи можно добавлять, а номера уже существующих лучше не менять.

**Если меняется формат сохранённых данных,** увеличьте `SCHEMA` в `assets/js/main.js` и добавьте перевод старого формата в функцию `migrate`. Сейчас действует схема 2: данные версий 0.1.x переносятся автоматически, неизвестные и испорченные поля отбрасываются, а испорченная запись целиком сохраняется рядом под ключом `atk-kbo:progress:corrupt`.

**Адрес сайта (необязательно).** Если вписать в `dev/modules.json` поле `"site": {"baseUrl": "https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/"}`, сборка добавит канонические ссылки, `sitemap.xml` и `robots.txt`.

## Безопасность и приватность

- Нет серверной части, аналитики, cookies, ключей API и внешних скриптов. Внешний ресурс один — шрифты Google Fonts; без них сайт работает на системных шрифтах.
- Файл прогресса при загрузке проверяется: принимаются только известные поля и допустимые значения, текст выводится без интерпретации как HTML.
- Тренажёры принимают только цифры и выводят результат безопасно.
